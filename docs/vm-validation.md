# Проверка сетевой политики IPGuard в Windows VM

Эта программа проверяет гипотезы из [технического исследования](technical-research.md). Все сценарии матрицы ниже имеют статус **не выполнено**. В репозитории реализован один отдельно включаемый тест жизненного цикла объектов; он пока не запускался в VM и не проверяет передачу пакетов.

## Условия запуска

Реальные изменения Firewall/WFP разрешены только после явного включения специального режима в изолированной Windows VM с административными правами, согласно [AGENTS.md](../AGENTS.md). Текущая рабочая машина для этих испытаний не используется.

Тестовый раннер проверяет отдельный opt-in, подтверждённое назначение VM для испытаний и права администратора до первого изменения. Одна только категория теста, наличие гипервизора или повышение прав не разрешает испытание. Обычный `dotnet test` пропускает изменяющий WFP тест с понятной причиной.

Для VM нужны снимок до установки, доступ к консоли независимо от сети, контрольные TCP/UDP-получатели для IPv4/IPv6 и отдельное приложение сравнения. Учёт пакетов ведётся также на стороне получателя: таймаут HTTP-запроса сам по себе не доказывает блокировку.

## Реализованный тест объектов

`scripts/Test-WfpVm.ps1` требует `-ConfirmIsolatedVm`, `-ConfirmSnapshot`, явные `-MachineName` и `-SnapshotName`, совпадение имени компьютера и административный токен. Эти аргументы подтверждает оператор: наличие настоящей изоляции и снимка из гостевой ОС автоматически не проверяется. Команда запуска приведена в README. Здесь этот режим не включался.

Перед тестом скрипт временно задаёт `IPGUARD_WFP_VM_ENABLE=1`, `IPGUARD_WFP_VM_CONFIRMATION=I_CONFIRM_THIS_IS_AN_ISOLATED_VM`, `IPGUARD_WFP_VM_MACHINE`, `IPGUARD_WFP_VM_SNAPSHOT` и абсолютный `IPGUARD_WFP_VM_RESULTS`. C#-проверка повторяет условия до любого нативного изменения и отказывает при наличии `CI`/`GITHUB_ACTIONS`, неподдерживаемой платформе или неизвестных правах. Скрипт запускает только `Category=WfpVm`; skipped/empty/missing/failed TRX не считается успехом. Прямое выставление переменных не является обходом требований изоляции и явного разрешения.

`PolicyObjects_CompleteRoundTrip` работает с отдельной копией `powershell.exe`, не выполняет её и не посылает трафик. Проверяются базовые объекты, динамический Permit, отказ удаления при активном Permit, закрытие сессии и повторное удаление. Проверка pristine namespace читает provider и sublayer независимо: частично установленная политика тоже препятствует запуску. Named mutex сериализует этот тест между процессами; это не реализация единственного владельца разрешения в продукте.

В `artifacts/wfp-vm/<run>/` сохраняются `run.json`, TRX, копия исполняемого файла и `journal.jsonl`: версия/редакция Windows, runtime, версия сборки, SHA-256, фактические GUID и поля связанных фильтров, UTC и монотонные отметки снимков. Это временные метки операций с объектами, а не задержки прекращения трафика. При ошибке сценарий не продолжает удаление baseline; Permit закрывается, если lease был получен, а ошибка закрытия сохраняет неопределённость. После ошибки нужно экспортировать данные и восстановить снимок VM, а не повторно запускать очистку.

Безопасные тесты проверяют условия запуска и контроллер на fake-сессиях. Успех этих тестов, а также будущий успех object round-trip не закрывает полностью ни один сетевой сценарий матрицы. Нативные изменения, арбитраж, загрузка, авария процесса и реальная блокировка остаются непроверенными.

## Наблюдаемые результаты

Для каждого запуска сохраняются версия и редакция Windows, разрядность и пути PowerShell, версии приложения, конфигурации и GeoIP-базы, собственные GUID фильтров, условия и флаги фильтров, события приложения и результат контрольного трафика. Логи не содержат секреты прокси и загрузки GeoIP.

Время измеряется монотонными часами отдельно для сетевого события, его обнаружения, отзыва Permit и последнего полученного пакета. Фиксируются задержка и число переданных байтов; нельзя заменять измерение словом «мгновенно». Для проверки локальной логики используется детерминированное время.

| W01 | Установка до первого запуска GUI | Собственная базовая блокировка действует без запущенного приложения; контрольное приложение работает. |
| W02 | Решение Block | TCP и UDP от зарегистрированных PowerShell заблокированы в обоих семействах. |
| W03 | Решение Allow в контролируемой сети | Динамические Permit пропускают только предусмотренный трафик; постоянные Block остаются установленными. |

| W09 | Зависание владельца разрешения | Проверяется способ отзыва устаревшего разрешения. Оставшийся без проверки Permit означает провал этого критерия. |

| W25 | Установка, обновление и сбой удаления | Прерванная операция не оставляет приложение в ошибочно разрешённом состоянии. |

## Безопасное завершение

Очистка использует только известные идентификаторы и проверку владельца. Нельзя удалять все правила по префиксу имени, сбрасывать Firewall или импортировать старый полный снимок поверх чужих изменений. При неизвестном состоянии сохраняется журнал и используется консоль VM либо восстановление её снимка.

Результат каждого испытания — «пройдено», «не пройдено» или «не выполнено» с приложенными наблюдениями. Если обязательный сценарий допускает трафик, выпуск разрешающего режима приостанавливается до изменения механизма либо явно согласованного изменения требований. Наличие работающей иконки трея и зелёных unit-тестов этот критерий не заменяет.
