# Проверка сетевой политики IPGuard в Windows VM

Эта программа проверяет гипотезы из [технического исследования](technical-research.md). Все сценарии ниже имеют статус **не выполнено**. Наличие программы не означает наличия реализованных или прошедших интеграционных тестов.

## Условия запуска

Реальные изменения Firewall/WFP разрешены только после явного включения специального режима в изолированной Windows VM с административными правами, согласно [AGENTS.md](../AGENTS.md). Текущая рабочая машина для этих испытаний не используется.

В тестовом раннере необходимо проверять отдельный opt-in, подтверждённое назначение VM для испытаний и права администратора до первого изменения. Одна только категория теста, наличие гипервизора или повышение прав не разрешает испытание. Обычный `dotnet test` должен безопасно пропускать изменяющие ОС проверки с понятной причиной.

Для VM нужны снимок до установки, доступ к консоли независимо от сети, контрольные TCP/UDP-получатели для IPv4/IPv6 и отдельное приложение сравнения. Учёт пакетов ведётся также на стороне получателя: таймаут HTTP-запроса сам по себе не доказывает блокировку.

## Наблюдаемые результаты

Для каждого запуска сохраняются версия и редакция Windows, разрядность и пути PowerShell, версии приложения, конфигурации и GeoIP-базы, собственные GUID фильтров, условия и флаги фильтров, события приложения и результат контрольного трафика. Логи не содержат секреты прокси и загрузки GeoIP.

Время измеряется монотонными часами отдельно для сетевого события, его обнаружения, отзыва Permit и последнего полученного пакета. Фиксируются задержка и число переданных байтов; нельзя заменять измерение словом «мгновенно». Для проверки локальной логики используется детерминированное время.

## Матрица испытаний

| Код | Сценарий | Критерий приёмки |
| --- | --- | --- |
| W01 | Установка до первого запуска GUI | Собственная базовая блокировка действует без запущенного приложения; контрольное приложение работает. |
| W02 | Решение Block | TCP и UDP от зарегистрированных PowerShell заблокированы в обоих семействах. |
| W03 | Решение Allow в контролируемой сети | Динамические Permit пропускают только предусмотренный трафик; постоянные Block остаются установленными. |
| W04 | Возврат Allow → Block | Новые подключения не проходят после завершения отзыва; измерен интервал перехода. |
| W05 | Завершение владельца сессии через аварийное прекращение процесса | Permit удаляются без выполнения finally и обработчика Exit; базовые фильтры остаются. |
| W06 | Холодная загрузка и перезагрузка без входа пользователя | Зарегистрированный тестовый запуск PowerShell до GUI не передаёт данные; проверен boot-time переход. |
| W07 | Провайдер без service association | После загрузки ОС базовые фильтры активны; собственный Windows Service отсутствует. |
| W08 | Остановка и восстановление BFE | Зафиксировано фактическое поведение без предположения, что persistent означает непрерывное применение. При утечке обязательная гарантия не пройдена. |
| W09 | Зависание владельца разрешения | Проверяется способ отзыва устаревшего разрешения. Оставшийся без проверки Permit означает провал этого критерия. |
| W10 | Ошибка посреди транзакции | Нет частичного набора Permit и окна из-за удаления базового Block. |
| W11 | Чужие Block, Allow и WFP hard permit | Чужая политика не изменяется; недопустимый конфликт обнаруживается. При обходе базовой блокировки конфигурация не считается поддерживаемой. |
| W12 | Действующий TCP, TLS/HTTP keep-alive и однонаправленный UDP | Измерены последние переданные данные после отзыва для IPv4/IPv6 и обоих направлений. Закрытие сокета и прекращение передачи различаются. |
| W13 | PowerShell слушает входящие TCP/UDP | Запрет нельзя обойти, сделав PowerShell принимающей стороной соединения. |
| W14 | VPN disconnect/reconnect и смена интерфейса | Прежнее разрешение аннулируется; маршрут резервного интерфейса не получает непроверенное разрешение. |
| W15 | Split tunnel и специфичный маршрут вне VPN | HTTPS-проверка через US не разрешает трафик по неподтверждённому пути. |
| W16 | IPv4 US и IPv6 другой страны либо неизвестен | Непроверенное семейство не пропускает трафик; общее решение соответствует строгой политике. |
| W17 | Прокси, PAC, переменные окружения и loopback-прокси | География прокси не выдаётся за общий выход; проверяется возможность обхода через локальный посредник. |
| W18 | Смена публичного IP без изменения локального адреса | Периодическая проверка выявляет изменение и отзывает разрешение в измеренное время. |
| W19 | Sleep/resume и изменение сети во время HTTPS | Старые результаты не применяются к новой версии сети. |
| W20 | DNS/HTTPS/TLS/GeoIP failures и конфликт источников | Ошибка проверки не оставляет действующим разрешение сверх принятого контракта свежести. |
| W21 | Разные пути, x86/x64, Store и portable PowerShell | Для зарегистрированных путей действует политика; неизвестные пути явно отражены как ограничение покрытия. |
| W22 | Закрытие окна, восстановление из трея и Exit | Закрытие окна сохраняет контроль; Exit отзывает разрешение. UI остаётся отзывчивым. |
| W23 | Второй экземпляр, другой пользователь и logoff | Нет конкурирующих владельцев разрешения, сохраняющих Permit после выхода владельца. |
| W24 | Помощник и IPC, если эта модель выбрана | Смерть GUI, отказ UAC и разрыв IPC не создают бессрочное разрешение. Посторонний процесс не может отдать команду Allow. |
| W25 | Установка, обновление и сбой удаления | Прерванная операция не оставляет приложение в ошибочно разрешённом состоянии. |
| W26 | Удаление и повторная установка | Удаляются только собственные подтверждённые объекты; чужие объекты и доступ контрольного приложения сохранены. |
| W27 | Удаление после удаления/перемещения PowerShell и смены конфигурации путей | Все подтверждённые старые Block находятся по сохранённому App ID без обращения к отсутствующим файлам; повторная установка проходит. |
| W28 | Удаление disabled-объектов после перезагрузки | Собственные объекты версии 1 распознаются для удаления; disabled не выдаётся за действующую блокировку. Проверены состав null-template snapshot и права чтения. |
| W29 | Удаление при активном Permit или неизвестной схеме | Предварительная проверка отказывает до первого delete. После ошибки baseline сохранён; чужие/неизвестные объекты не изменены. |
| W30 | Скрытые правами чтения зависимости, чужие ссылки, callout/provider context | Ошибка удаления sublayer/provider не игнорируется и откатывает всю транзакцию; нет принудительной очистки зависимостей. |
| W31 | Несколько страниц фильтров и ошибки удаления/readback/cleanup | Проверены границы страниц, освобождение памяти/enum handle, readback собственных изменений в транзакции, откат и диагностика. Ошибка close после commit не выдаётся за отмену commit. |

## Безопасное завершение

Очистка использует только известные идентификаторы и проверку владельца. Нельзя удалять все правила по префиксу имени, сбрасывать Firewall или импортировать старый полный снимок поверх чужих изменений. При неизвестном состоянии сохраняется журнал и используется консоль VM либо восстановление её снимка.

Результат каждого испытания — «пройдено», «не пройдено» или «не выполнено» с приложенными наблюдениями. Если обязательный сценарий допускает трафик, выпуск разрешающего режима приостанавливается до изменения механизма либо явно согласованного изменения требований. Наличие работающей иконки трея и зелёных unit-тестов этот критерий не заменяет.
